# 双工倾听与自然话轮

状态：0.17.3（build 33）保留 1.6 秒续说窗口，修复未完成输入抢答及识别冲突；原生 130/130、电话 120/120 通过，已安装并通过隔离启动检查；保留当前聊天进程，重新打开后使用新版。实际接口回放与识别失败边界见[语音可靠性验证](../007-voice-reliability/spec.md)。真人现场识别率、儿童及多人环境仍未验收。更新：2026-11-17。产品基线：[product.md](../product.md)。

## 问题与目标

0.11 把 VAD 的声音开始当成打断；0.12 又过度保护段落，普通问题会等待很久，并且只识别少数固定口令。用户实测指出“实际上没办法打断”。目标是持续双工收听，根据新内容的重要性让话，同时避免被附和和杂声打断。

已确认的链路缺口：`gpt-transcribe` 在音频提交后才开始处理，返回 delta 不等于提交前实时识别。0.13 已通过接口探针确认同一 Realtime 会话支持 `gpt-live-transcribe` 的提交前转写，保留现有语义 VAD；继续保持收音、识别、插话判断、回复与播放相互独立；不能把播放锁误当成双工控制。

## 行为决定

2026-11-17 再次实测抢答：1.6 秒常量及安装版本均未回退，但计时取消原先仅依赖云端重新开口事件；最终意图的 wait 还会被转换成 listen。现已实现：本机连续至少 80 ms、RMS 至少 0.003 的声音先延缓旧提交，等待云端确认；本机电平只延缓提交，不能自行产生请求或打断播放。短暂噪声不延缓，额外等待超过 4 秒仍不断收到声音而没有云端分段时提示重说，不提交半句。对“哦，我说……”等不完整开头及最终 wait 保留本轮，下一段完整后才按原 1.6 秒规则提交，不用附加一句“我在听”抢话。明确停止仍立即生效。

真实接口回放又复现了已转写正确的诗句被对象判断丢弃。安静等待或问题后的准确诗句命中视为有意义的交流；称呼/引用审查仍在前，播放重叠时继续走回声和对象判断。其余续说也在语义提示中明确不需要有问号或命令。

2026-11-17 等待时长调整：用户实测认为 2 秒偏长，明确改为 **1.6 秒**。仅调整续说缓冲，保留音频复核、取消/纠正、连续双工和明确停止的快速路径；实现与验证结果见 0.17.1 记录。

2026-11-16～17：用户再次报告成人 USB/有线耳机识别差、无法取消错误请求。新增[语音识别、取消与纠正规格](../007-voice-reliability/spec.md)，最终音频复核、统一文本输入和显式取消/纠正已替换此前仅凭实时字幕及原始音频回答的链路；续说时长按上方最新决定，双工和对象判断约束继续适用。

2026-11-17：最终复核后的“给我画…”“帮我讲/读…”具有直接面向伙伴能力的线索，可走接话快速路径，避免再等一次云端分类。称呼、引用、转述先行检查；“小明，给我画…”仍经对象判断。自然的“听一下”也视为让出话权的请求，不改写转写文字来掩盖“停/听”的混淆。

2026-11-16～17 续说修正：用户反馈一句话因短暂停顿被拆成多个“我说”气泡。云端音频分段不等于一轮对话结束；客户端在最终转写及对象判断完成后保留 1.6 秒续说窗口，窗口内重新开口即取消本次提交，待后续片段完成后重新等待。等待时保持“在听”与完整的本轮文字预览；重要插话仍可立即暂停莉莉，明确停止仍不等待续说窗口。历史 1.5 秒、2 秒版本的证据分别保留在对应版本记录中。

同一轮接受的转写片段按说话顺序合并，只产生一个用户消息、一次会话记录和一次回复；不把识别服务的 item 数量当作消息数量。拼接保留原字词和标点，中文不额外插换行，英文词边界保留空格。已提交后的新发言仍是新一轮。静音、挂断或改发文字时，尚未提交的旧片段和定时任务不能继续发出回复；旁人话语、回声和失败转写仍按原规则处理。

真实接口回放补充：仅延长窗口仍会丢失后半句。“给我讲一个”与“小马过河的故事”都正确转写后，旧对象判断孤立处理第二段，将其忽略。对象判断必须携带同轮前文；较早片段尚未转写完成时，后续普通片段暂缓判断，防止因回调乱序缺上下文而丢字。明确停止保留优先处理。前文只提供续说语境，不能把当前明确转向旁人的话强行当作对莉莉说。

2026-11-16 补充（已实现）：交谈对象判断同时覆盖播放期间和安静等待期间。向旁人的称呼、转述/引用等线索先于问题与停止的快速路径；“妈妈，你能帮我拿水吗”不能仅因为含问题词就让莉莉接话。生产入口的一般问题经过语义对象判断，明确呼叫莉莉的提问与清楚的停止保留快速处理。当前内容的纠正和问题后的短答仍正常处理。语义判断失败时，明确旁人事务保持旁听，清楚的直接请求仍可接话；不能把所有含“妈妈”的话都过滤。

此能力只根据文字和上下文估计话语对象，不识别人脸、声纹、年龄或说话人身份。没有文字线索的其他人发言、电视对白、多人同时说话仍可能误判；不保存声纹或原始录音，也不要求每句呼叫莉莉。

| 当前状态 / 输入 | 行为 |
| --- | --- |
| 任意状态：挂断 | 立即停止采集、播放、生成和待处理请求。 |
| 明确说“停一下 / 暂停 / 别讲了”及自然变体 | 连续识别到完整意图后及时停止，不依赖末尾标点或限定口令格式；不等段落末尾、不自行续讲。否定和引用仍要区分。 |
| 明确说“听我说 / 我想问个问题 / 等一下，我…” | 让出话权，保留后续实际发言；不把这类请求当作附和。 |
| 故事中：短促声音、空/失败转写、回声 | 不取消当前播放，不改成“在听”，不产生新回复。 |
| 故事中：“嗯 / 哦 / 对 / 好 / 哈哈”等单纯附和 | 继续讲，不产生“我在听”或“继续”的额外回复。 |
| 故事中：纠正、新问题、拒绝当前内容、明确的新请求或重要分享 | 结合正在讲的内容判断，及时让出话权听完，不要求先说“停一下”。不能排队几十秒到段末。 |
| 故事中：不要求回应的轻量评论 | 可保持当前讲述或在自然间隙接上；判断不可用时不得把清楚的真实请求永久锁住。 |
| 段落边界时孩子还在说话 / 转写未完成 | 等孩子说完；若只是空声或附和，从下一段继续，不重播已讲部分、不重新调用模型续写。 |
| 普通聊天中：确认了实际新请求 | 自然让出话权，不套用故事的整段保护。 |
| 正在等待回答或刚问完问题：“好 / 对”等短答 | 当作真实回答，不能一律过滤为附和。 |

本表针对语音发言；主动发送文字视为明确的新请求，直接让出。

输入结束与是否让话是两个决定。只收到 VAD 事件不得取消回复；但不能只等最终转写才听到打断。关闭服务端自动打断，由客户端结合连续转写和语义决定，实际答复仍等待用户说完。

## 播放与上下文

- 默认 A「温柔老师」不变。模型输出故事时分为自然小段，每段通常 2～3 句，避免整篇长故事占住一个播放单元。
- 本机 TTS 每个自然段连续生成，不按逗号切片；段落边界取音频真正播放结束回调，不能把“模型生成完”当成“用户听完”。较长、没有分段的文本只在完整句子边界补分段。
- 重要新内容可以越过段落边界。段落保护只用于维持无实质插话时的流畅讲述，不能充当拒绝接话的锁。
- 暂定重要内容时可先暂停现有播放、继续收听；确认是附和/误识别时，从原播放位置恢复。明确停止则取消，不自动重播。
- 云端备选声音没有可靠的字词音频对齐，使用当前短回复的实际播放结束作为边界；明确停止仍随时有效。不用估算字数伪造“已听到哪里”。
- 被接话打断的后续段不自动恢复。当前 Realtime 会话上下文应保留完整听过的段落，并标明当前段/后续未完整播放；不得宣称已经听完全文。
- 迟到转写、旧生成任务、重复播放结束事件不得取消新回复或把已取消的故事重新播出。
- 识别失败的短声不能让正在讲的段落静音；若在边界等待识别，失败/超时后继续剩余段落。

## 方案依据与取舍

- 声音持续采集，播放/暂停不关闭麦克风。Realtime 会话保留 `gpt-live-transcribe` 作为连续预览、保留语义 VAD，关闭服务端自动生成和打断。0.17 在上传音频的内存时间线上复核最终语音，用同一份最终文本替换服务端音频输入后才回答，详见语音可靠性规格。转写专用会话的 VAD 限制不能直接套用到对话会话。
- 0.13 同一份 16 秒录音曾验证提交前/后的差别，并选择 `low` 优于 `minimal`。0.17 根据中文识别反馈，将连续预览改为 `medium`，移除额外云端远场降噪，保留本机回声处理；最终准确性由独立音频复核与实测跟踪，不把预览速度当作最终识别质量。[OpenAI 实时转写](https://developers.openai.com/api/docs/guides/realtime-transcription)。
- 明确控制、附和和显然的新问题有快速路径；其余文字结合当前讲话内容交给既有 OpenAI 文本模型判断，区分让话、停止、继续听旁听反应、暂待更多文字。判断“先听用户”不等于“立刻回答”，答复仍等用户说完。
- 语义判断有 2.5 秒期限，失败或超时不得把完整请求锁在段末；晚到结果不能覆盖新轮次。明确停止优先，也取消更早的未完成请求；已删除的输入不重复删除，避免协议错误结束通话。
- 实时部分文字判为重要时先暂停现有播放，保留缓冲和收音；最终确认是附和/误识别时原位恢复，确认是真请求时取消旧内容并处理新发言。
- 桌宠和主窗口分开显示说话/收音信号，实时文字在桌宠可见，不要求切回主窗口确认是否被听到。

参考成熟话轮系统将 VAD、附和、真正插话和误打断恢复分开的做法；没有声称接入 LiveKit 的声学模型。[LiveKit 自适应打断](https://docs.livekit.io/agents/logic/turns/adaptive-interruption-handling/)。当前语义判断仍有网络延迟，且不等同于声纹识别；不同儿童发音、口音、电视背景和多人混说仍需现场观察。

## 2026-11-16 成人中文识别评估

用户补充：成人单独说话时也频繁识别错误，截图中的“是一个老巫婆”显示成“这个”只是其中一次。本次不再把主要原因限定为儿童音高、轻声或重叠发言；此项评估本身未更换识别模型，后续 0.16.1 的续说修正见上节。

- 当前显示链路：服务端 `input_audio_transcription.completed.transcript` 经 `VoiceTurns.finish`、`onUserText` 写入 `ChatMessage.text`，气泡直接显示全文，没有中文截字或语义改写。没有当次原音频，不能据此断定截图中缺失发生在收音、分句还是转写。
- 当前理解链路：`gpt-realtime-2.1` 直接消费音频；`gpt-live-transcribe` 的转写用于显示、意图判断和本机工具上下文，未替换服务端的用户音频消息。字幕与回答并不保证基于同一份文本；仅升级字幕模型不足以保证回答跟随正确转写。
- 固定接口回放：6 段合成中文语音（含一个同句轻声变体）和 1 段合成噪声，对比当前 `low + far_field`、`low + 无额外降噪`、`medium + 无额外降噪`、句末 `gpt-transcribe + 无额外降噪`。4 组共 28 次独立会话均完成，同一测试项的 PCM 相同，参考答案未放入请求；未打开麦克风或物理播放。完整输入、源码与结果见 [评估清单](../../artifacts/asr-evaluation-20261116/evaluation-manifest.json)、[逐项对比](../../artifacts/asr-evaluation-20261116/comparison.json)。
- 本组结果：当前配置把“不是奶奶，是一个老巫婆”识别为“不是ないない是一个老屋火”；`medium` 和句末模型在该样例中正确。单独关闭远场降噪也把“老巫婆”识别成“老物活 / 老屋伙”，不能将关闭降噪视为通用修复。忽略标点后的严格逐字匹配分别为 3/6、2/6、4/6、4/6；四组噪声均无转写。严格指标计入声学上无法区分的“他/它”和“小雨/小宇”，不代表这些差异均为听音错误，也不能把这个小样本比例当成产品准确率。
- 候选方向：保留连续预听及实时让话，在句末用准确率优先的识别结果统一显示、对象判断和回答输入；现有连接可评估 `gpt-transcribe` 的第二遍复核，新增供应商优先比较豆包流式识别 2.0 的 `enable_nonstream` 二遍模式及 Qwen-Audio 3.1 ASR。它们只替换/补充识别，不改变 A 声线、角色、双工和授权复用约束。此处是候选设计，尚未接入二遍或新供应商。

- 尚未验证：用户本人原音频、实际输入设备与音频处理影响、复杂背景、长会话、实际打断时延和听感。诊断直接输入合成 PCM，绕过 Mac 物理收音/回声处理以及 App 的话轮与 UI 逻辑，不能据此宣布现场问题已解决。未改生产 Swift 或安装包，本轮只检查诊断结果和规格链接，未重跑原生/电话全套回归。
