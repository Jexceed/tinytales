# 会话标题与时间

状态：已实现并安装 0.17.2（build 32）；代码回归与原生窗口渲染检查通过。日期：2026-11-17。产品基线：[product.md](../product.md)。

## 需求与变更原因

用户截图中的历史会话都叫“新的小冒险”，无法判断聊过什么；希望标题下面有一行小字时间。原实现会把故事的默认标题覆盖到会话标题，而且侧栏没有展示已有的故事更新时间。

## 设计决定与边界

- 优先保留具体故事题名；标题为空或为“新的小冒险”等通用占位词时，从实际故事摘要提取简短内容。文字和电话共享此规则，新存档也保存可辨认的标题。提取只压缩已有文字，不编造人物、情节，不额外请求云端。
- 旧摘要中的“好呀”“当然可以呀”等开场白跳过；明确引用的故事/成语名优先，连环画优先提取第一格内容。其余取简短内容片段，最多 20 字加省略号。这是本机内容摘取，不承诺对任意文本都得到语义最佳的概括。
- 已有存档在显示时应用相同规则，因此更新后旧记录即可辨认；无需重写或删除旧数据库记录。侧栏、打开后的标题和删除确认显示一致。
- 未存档的普通聊天继续使用首条有效用户内容起名；不把隐私输入放入标题，不为草稿、接通电话或助手问候创建空白会话。
- 标题最多显示两行，下面以较小、较淡的字显示日期和 24 小时时间，例如“11月17日 14:32”；跨年记录包含年份。悬停和辅助功能提供完整日期及时间。按照系统时区显示，非法旧时间明确显示“时间未记录”，不伪造当前时间。
- 运行中的会话记录最近一次有效用户提交或故事存档时间；切换缓存时保留。旧存档使用已有 `updatedAt`，不能将它说成原始创建时间。打开、切换、刷新不改变时间，也不重排记录；继续对话可更新时间，但保持已有行的位置和 ID。
- 不新增原始对话落盘；不改变历史存档、删除、配图、声音、签名和授权复用规则。

## 验收与追踪

| ID | 必须验证的行为 |
| --- | --- |
| CL-001 | 旧的同名占位存档按各自摘要展示内容标题；打开、切换和重启后规则一致，具体题名与原始存档保持。 |
| CL-002 | 文字及共享故事存档遇到空白/通用题名时从实际内容取名；新标题不再退回默认“小冒险”，明确题名保持。 |
| CL-003 | 普通聊天时间随有效提交更新，缓存切换、刷新、存档更新都不重排行或丢失标题/时间；空白输入不创建记录。 |
| CL-004 | 时间包含日期、时分，跨年包含年份；支持现有 ISO 时间与小数秒、系统时区，损坏时间不显示为现在。 |
| CL-005 | 电话接通/问候不创建记录，最终识别后的内容可以命名并计时，故事完成使用内容标题，切换后保留。 |
