# 会话切换与后台生成

状态：已实现。0.18.1 保留调整时长时的后台请求与草稿，原生、电话回归及原生窗口回放通过。更新于 2026-11-18。产品基线见 [product.md](../product.md)。

## 原行为与变更原因

用户报告模型工作时切换 session，切回来只剩提问、没有回复。原实现由当前选中视图持有唯一任务、引擎和故事上下文；切换/新建调用 `cancel()`，缓存又过滤流式消息。新的决定：切换只改变正在查看的会话，已经发送的请求继续接收。

## 需求与设计决定

- 每个运行中的会话持有独立的引擎、故事上下文、任务、请求标识和流式消息 ID。回调按会话与本轮请求定位，不能写入当时恰好选中的另一会话。
- 切换或“新对话”保留原任务和已显示的流式内容；切回来可以继续看生成。同一会话在生成时仍只允许一个请求，不同会话可分别生成。
- 文字、图库回复、故事存档和画图都应用相同归属规则。后台故事保存后不产生第二个侧栏记录，原行 ID 与相对顺序不变；消息、标题、时间、草稿、配图和后续上下文分别保留。
- 侧栏显示正在生成、有未查看回复或回复失败的状态；打开后清除未读标记。后台失败留在原会话，返回时显示错误及可重试的草稿，不能覆盖后来输入的草稿。
- 后台完成不自动朗读；回到已经完成的会话也不自动重播。前台完成仍使用原来的朗读设置，其他会话完成不能打断当前电话。
- 明确“停一下”仅取消当前会话请求；删除会话在数据库删除成功后取消该会话任务。已取消/删除任务的迟到事件不得发布、存档或恢复侧栏；其他会话继续工作。删除失败保留原任务与数据。
- 停止后允许直接发送下一条请求；旧任务结束时不能清除新任务的忙碌状态。每轮回调单独捕获，原引擎的对话上下文和会话时间限制继续保留，不靠重建引擎重置时限。
- 清空数据、影响上下文的设置/连接变更继续作废全部会话和任务。只要数据修订失效，旧请求不能落盘。
- 正在通话时保留既有会话切换限制，不在此次引入多路麦克风或后台通话。切换文字会话时停止当前自动朗读，但不停止模型生成。
- 任务在 App 进程内继续运行；退出 App 不承诺后台续跑，也不新增原始聊天持久化。已被旧版取消的请求不能自动找回，不偷偷重发历史提问。

## 验收与追踪

| ID | 必须验证的行为 |
| --- | --- |
| BG-001 | 生成期间切换/新建，再返回仍可接收流式内容与最终回复；当前视图不被原会话覆盖。 |
| BG-002 | 两个会话可同时生成并乱序完成；各自消息、标题、时间、草稿和上下文不串线，也不重复发出同一请求。 |
| BG-003 | 后台故事与配图归属原会话，存档后不增行、不重排；继续聊天使用原会话的完整上下文。 |
| BG-004 | 生成、未读完成、失败状态可辨认；后台失败可返回重试，保留用户后写的草稿。 |
| BG-005 | 显式停止/删除只取消目标任务，迟到流式/最终结果不能复活；删除失败不部分取消，其他会话不受影响。 |
| BG-006 | 全局数据/连接修订作废全部任务；切换仍不持久保存原始聊天。 |
| BG-007 | 后台完成不触发自动朗读、不改变当前通话；电话结束后仍能查看原会话回复。 |
| BG-008 | 调整“每段对话”的时长保留前后台对话、草稿、运行中的请求与原有截止时间。下一个开始计时的对话使用新时长。 |

2026-11-18 检查发现，修改时长会使所有会话和请求作废，与设置界面“对新对话生效”冲突。时长是开始计时的参数，调整它无需清除上下文。记忆设置和连接的失效规则继续适用。
